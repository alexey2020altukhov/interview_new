## Kafka
### Что такое Kafka? 
Kafka — гибрид распределённой базы данных и брокера сообщений. 
### Кто такой Publisher (Producer) и Subscriber (Consumer)? 
Producer — компонент, который публикует сообщения в Kafka. 

Consumer — компонент, который читает сообщения из Kafka. 
### Что такое topic? 
Topic — логическая категория/журнал, в который producer отправляет сообщения, а consumer читает их. 

Топики разделяются на партиции, что позволяет распределить данные по брокерам. Каждая партиция реплицируется на несколько брокеров.
### Что такое партиции и зачем они нужны?
Partition — отдельная упорядоченная часть topic. 

Партиции используются для параллельной обработки и масштабирования. Topic разбивается на несколько партиций, и consumer'ы одной группы могут одновременно читать разные партиции. Это позволяет масштабировать обработку. При этом порядок сообщений гарантируется только внутри одной партиции. Поэтому если для одного объекта важен порядок, обычно используют одинаковый key.

Количество партиций фактически задаёт максимальный уровень параллелизма внутри consumer group.

Partitions могут находиться на разных брокерах.

Сообщения распределяются по партициям по ключу партицирования. От каждого сообщения считается hash-функция и высчитывается остаток от деления на число партиций

### Что такое broker?
Broker — сервер Kafka, который хранит partitions и обрабатывает запросы producer'ов и consumer'ов.

Брокеры используются для отказоустойчивости и содержат в себе копии сообщений. Обычно брокера 3.

### Что такое Consumer Group?
Consumer Group — группа потребителей, которые совместно обрабатывают сообщения из топика, каждая партиция читается только одним потребителем из группы.
Потребители делят партиции между собой — растёт пропускная способность. При падении потребителя его партиции подхватывают другие из группы.
Если потребителей больше, чем партиций, то лишние потребители простаивают — они не получают сообщения.

Параллелизм ограничен числом партиций: больше потребителей ≠ больше параллельной обработки.
При сбое работающие потребители подхватят нагрузку, так что «запасные» нужны как резерв для отказоустойчивости.

### Для чего нужна ребалансировка?
Ребалансировка — механизм, при котором Kafka перераспределяет партиции между consumer'ами группы.

Когда происходит rebalance Consumer Group:
- Подключился новый consumer к группе.
- Consumer вышел из группы.
- Consumer упал или перестал отправлять heartbeat.
- Превышен session.timeout.ms — Kafka считает consumer недоступным.
- Превышен max.poll.interval.ms — consumer слишком долго не вызывает poll().
- В topic добавились новые партиции.
- Изменился состав consumer'ов группы по любой другой причине, требующей нового распределения партиций.

### Что такое offset?
Offset - номер первого непрочитанного сообщения внутри партиции.

Подписчики, которые читают записи сообща (параллельно), находятся в одной consumer-группе имеют общие offset'ы.

### Что такое реплика?
Реплика — это копия партиции на другом брокере. Она служит для обеспечения отказоустойчивости и увеличения пропускной способности.

### Как удаляются сообщения из топиков?
Удаляются сообщения согласно 2м стратегиям: по времени (default- неделя) или по размеру очереди.

### Как происходит чтение сообщений?
Consumer делает poll() и получает пачку сообщений. После изучения новой пачки фиксируется новый offset. Настройка max.poll.records определяет максимальное количество сообщений, которое consumer получит за один вызов poll().

Время чтения одной пачки сообщений настраивается через max.pool.intervals.ms. Если consumer не успевает прочитать сообщения за отведенное время, его отстраняют, заменяя следующим, группу перебалансируют.

### Для чего применяют Kafka?
Кафку применяют для:
- Асинхронное взаимодействие. Нам не важен ответ; Последующее действие не зависит от результата асинхронной операции
- Амортизация нагрузки. Отправителю не нужно ждать, когда принимающая сторона обработает всю инфу.
- Потоковая обработка данных. Возможность обрабатывать большое количество сообщений в секунду.
- Репликация данных. Мастер-система пушит в кафку каждое изменение данных, Системы считывают изменения и актуализируют собственные копии мастер-данных.
- Event-driven architecture.
